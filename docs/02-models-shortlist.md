# 02. Отбор LLM: кандидаты под M4 Pro 24 GB

> Статус: v0.1 (2026-10-12), шорт-лист **до** бенчмарков. Финальный выбор ролей — после прогона `bench/` (docs/03-models-benchmark.md).
> Источник по размерам: страницы библиотеки ollama.com (октябрь 2026). Бенчмарки вендоров — заявления производителей, перепроверяем своими тестами.

## 1. Бюджет памяти

- 24 GB unified memory. Metal по умолчанию даёт GPU ~2/3–3/4 RAM (`iogpu.wired_limit_mb=0` → дефолт ≈ 16–18 GB).
- При желании лимит поднимается вручную: `sudo sysctl iogpu.wired_limit_mb=20480` (сбрасывается при перезагрузке). Делает пользователь сам.
- Плюс KV-cache: на 32k контекста у 27–30B модели это ещё 2–6 GB.
- **Вывод:** модели на 18 GB (27–31B в Q4) загружаются только по одной и без запаса. Рабочая конфигурация для **одновременной** работы worker + validator + router — модели по 4–12 GB.

## 2. Критерии отбора кандидатов

| # | Критерий | Почему важно для агента |
|---|---|---|
| K1 | Влезает в память (вес + KV-cache) | Иначе свопинг и падение скорости в десятки раз |
| K2 | Свежесть (релиз ≤ ~12 мес.) | Ред-флаг задания; старые модели заметно хуже в tool calling |
| K3 | Нативный tool calling (тег `tools` в Ollama) | Основа агентности |
| K4 | Thinking с отключением | Reasoning там, где нужно; дешёвый режим для простых шагов |
| K5 | Семейство | Валидатор обязан быть **из другого семейства**, чем исполнитель |
| K6 | Лицензия (Apache 2.0 / MIT предпочтительно) | Учебный проект, но хорошая практика |
| K7 | Есть MLX-сборка | Быстрее на Apple Silicon |
| K8 | Заявленные агентные бенчмарки (MCP Atlas, τ-bench, TerminalBench, BFCL) | Предварительный фильтр перед своими тестами |

### 3.2 Jev-like (decision) модели — control plane

Jev (TypeSafe AI, 15.09.2026) — **System One** модель: не генерирует текст, а возвращает распределение вероятностей над заданными вариантами. Три примитива: `choice` (выбор варианта), `noul` (вероятность «да»), `score` (оценка по шкале) + `confidence`. Веса закрыты, доступна только через API (`api.typesafe.ai/v1/systemone`, $0.042 / 1M входных токенов, выход бесплатно; новые регистрации приостановлены с 22.09).

Локальные Jev-like модели с тем же API (`/v1/systemone` в Ollama ≥ 0.35):

| Модель | Вендор | База | Размер | Точность (13 датасетов, Bespoke Labs) | Контекст на деле |
|---|---|---|---|---|---|
| `tev1:0.8b` | Together AI | Qwen3.5-0.8B | 0.8 GB | 63.5% | ~2k |
| `tev1:4b` | Together AI | Qwen3.5-4B | 4.5 GB | 73.3% | ~2k |
| `nimble:9b` | Bespoke Labs | Qwen3.5-9B | 9.4 GB | 75.7% | 8k |
| `laya` | Convai | ModernBERT-large 421M | <1 GB | — | — |
| *Jev 1.13 (API, эталон)* | TypeSafe | закрыта | — | 76.0% | 32k |

**Роль в системе (гипотеза):** роутер сложности запроса (`choice`: simple / complex / dangerous), выбор skill, быстрые проверки валидатора (`noul`: «есть ли в плане деструктивная команда?», «опирается ли вывод на логи?»), оценка уверенности для каскада («малая модель уверена → отвечаем, иначе → большая»).

> ⚠️ Важная деталь для защиты: tev1 и nimble **дообучены из Qwen3.5**. Если исполнитель — Qwen, то Jev-like проверки валидатора формально тоже «семейство Qwen». Поэтому финальный вердикт валидатора даёт LLM другого семейства (Gemma/Granite), а Jev-like — только дешёвый предфильтр.

### 3.3 Отсеяны (с причиной)

| Модель | Причина |
|---|---|
| `nemotron-3.5-lightning:30b` (NVIDIA, MoE 3B акт.) | 23–25 GB — не влезает в GPU-лимит 24 GB машины |
| `qwen3.6:35b` | 23–24 GB — не влезает |
| `gemma4:31b` dense | 19–20 GB + KV-cache — на грани, медленнее 26B MoE при близком качестве |
| `mistral-medium-3.5:128b`, `laguna-s-2.1` 118B | Не влезают |
| GLM-5.3, DeepSeek V4, Kimi K3, Mistral Large 4 | Только облачные/огромные — рассматриваем как облачный уровень, не локально |

### 3.4 Эмбеддинги (для памяти)

`embeddinggemma-2` (270M–740M) — кандидат №1 (лёгкая, мультиязычная); альтернатива — `qwen3-embedding`. Выбор — на этапе памяти.

## 4. Предварительная схема ролей (проверим бенчмарком)

| Роль | Кандидат | Fallback |
|---|---|---|
| Control plane / роутер (Jev-like) | `tev1:4b` | `nimble:9b`, Jev API |
| Worker — лёгкий уровень | `granite4.2:8b` или `ornith:9b` | `gemma4:12b` |
| Worker — тяжёлый уровень (квантованный) | `qwen3.8:27b` или `muse-glimmer:30b` | облачный уровень |
| Validator (другое семейство) | `gemma4:12b` (Google) | `granite4.2:8b` (IBM) |
| Облачный уровень (опционально) | см. §5 | — |

## 5. Дешёвые облачные API (опциональный уровень роутинга)

Цены по сторонним агрегаторам и странице Ollama Cloud — **перепроверить на официальных страницах перед использованием**.

| Вариант | Цена (вход / выход за 1M) | Плюсы | Минусы |
|---|---|---|---|
| Google AI Studio (Gemini Flash) | бесплатный tier | Без карты, хорошее качество | Данные бесплатного tier используются Google для обучения → только синтетические инциденты |
| Ollama Cloud (`glm-5.3-flash`, `deepseek-v4.1-flash`) | ~$0.15/$0.50, ~$0.30/$1.20 | Тот же API, что локально, — роутинг тривиален | Нужен аккаунт Ollama |
| DeepSeek API напрямую | ~$0.14–0.30 / $0.28–1.20 | Очень дёшево | Серверы в КНР |
| OpenRouter `:free` модели | $0 (50 req/день без пополнения) | Много моделей через один ключ | Лимиты, нестабильный состав |
| TypeSafe Jev | $0.042 / бесплатно | Оригинальный Jev как эталон для сравнения с tev1/nimble | Регистрация приостановлена; можно через Vercel AI Gateway |

**Рекомендация:** основной режим — полностью локальный. Облачный уровень подключаем через LiteLLM как fallback и для сравнения; в первую очередь бесплатный Gemini (AI Studio), если понадобится — Ollama Cloud.
